title: "Как работают команды"
---

**Главное, что нужно знать: у OpenSpec есть два типа команд, и они выполняются в разных местах.**

- Команды `openspec ...` выполняются в **терминале**. (Например, `openspec init`.)
- Команды `/opsx:...` вводятся в **чате с ИИ-ассистентом**. (Например, `/opsx:propose`.)

Если вы введёте `/opsx:propose` в терминале и ничего не произойдёт, вот почему. Вы обращаетесь не к той части OpenSpec. Slash-команды — это не команды терминала, а инструкции для ИИ-ассистента, которые вводятся в том же чате, где вы обычно пишете, например: «добавь форму входа».

Это различие чаще всего вызывает затруднения у новых пользователей, поэтому давайте разберём его подробнее.

## Две части

У OpenSpec две роли.

**CLI (часть для терминала).** Программа `openspec`, которую вы устанавливаете и запускаете из командной оболочки. Она настраивает проект, выводит список изменений и проверяет их, показывает панель и архивирует завершённую работу. Команды вводятся в iTerm, терминале VS Code, PowerShell — везде, где вы запускали бы `git` или `npm`.

```bash
openspec init        # настроить OpenSpec в этом проекте
openspec list        # посмотреть активные изменения
openspec view        # открыть интерактивную панель
```

**Slash-команды (часть для чата).** Короткие команды, такие как `/opsx:propose` и `/opsx:apply`, которые вы вводите в ИИ-ассистенте. Они указывают ИИ следовать рабочему процессу OpenSpec: составить предложение, написать спецификации, реализовать задачи из списка и архивировать работу после завершения. Вводить команды можно в Claude Code, Cursor, Devin Desktop, Copilot или другом используемом вами ассистенте.

```text
/opsx:propose add-dark-mode    (вводится в чате с ИИ)
/opsx:apply                    (вводится в чате с ИИ)
/opsx:archive                  (вводится в чате с ИИ)
```

Модель работы в одной схеме:

```text
        ВАШ ТЕРМИНАЛ                         ЧАТ С ИИ-АССИСТЕНТОМ
   ┌──────────────────────┐               ┌──────────────────────────────┐
   │  $ openspec init     │ устанавливает│  /opsx:propose add-dark-mode  │
   │  $ openspec list     │  ──────────►  │  /opsx:apply                  │
   │  $ openspec view     │   команды     │  /opsx:archive                │
   └──────────────────────┘    & skills   └──────────────────────────────┘
       запускайте openspec здесь               запускайте /opsx:* здесь
```

Обратите внимание на стрелку. Именно выполнение `openspec init` в терминале *устанавливает* slash-команды в ИИ-инструмент. Терминальная часть настраивает часть для чата. После этого повседневная работа в основном выполняется в чате.

## «Как запустить интерактивный режим?»

**Отдельного интерактивного режима нет.** Этот вопрос задают часто, поэтому ответим прямо.

Не нужно переходить в специальный режим OpenSpec. Просто откройте ИИ-ассистента как обычно и введите slash-команду в чат. Именно slash-команда позволяет «войти» в OpenSpec. Ассистент распознает её, загрузит соответствующий навык OpenSpec и начнёт выполнять рабочий процесс.

Итак, нужно сделать следующее:

1. Откройте проект в ИИ-ассистенте (Claude Code, Cursor, Devin Desktop и т. п.).
2. Введите `/opsx:propose` в чате, где вы пишете любые другие запросы.
3. Следите за автодополнением: если OpenSpec установлен, при вводе slash появятся `/opsx:propose`, `/opsx:apply` и другие команды.

Вот и всё. Не нужно переключать режим, запускать службу или открывать отдельное окно.

В терминале есть одна действительно интерактивная функция — `openspec view`. Она открывает панель для просмотра спецификаций и изменений. Но это средство просмотра, а не инструмент, с помощью которого вы предлагаете и создаёте изменения. Разработка ведётся через slash-команды в чате.

## Зачем нужно такое разделение

Это разделение важно понять: оно объясняет, почему OpenSpec работает более чем с 30 ИИ-инструментами.

CLI — это **движок**. Он знает правила: структуру папок изменений, зависимости между артефактами и то, как объединять дельта-спецификацию с источником истины. Эти правила одинаковы везде.

Slash-команды — это **руль**, который немного различается в каждом ИИ-инструменте. Claude Code называет их командами, Cursor и Devin Desktop используют собственные форматы, а некоторые инструменты называют их навыками. При выполнении `openspec init` OpenSpec создаёт файлы нужного формата для выбранных инструментов, поэтому одно и то же действие `/opsx:propose` работает в любом выбранном вами ассистенте.

Преимущество такой схемы в том, что рабочий процесс изучается один раз и переносится между инструментами. Компромисс в том, что синтаксис команды может немного различаться; об этом — следующий раздел.

## Синтаксис slash-команд в разных инструментах

Назначение команд везде одинаково. Написание зависит от файла, который загружает инструмент.

| Файл команды для инструмента | Как вводить команду | Примеры инструментов |
|--------------------------|-----------------|---------------|
| `.../commands/opsx/<id>.*` | `/opsx:propose` | Claude Code, Gemini CLI, Crush |
| `.../opsx-<id>.*` | `/opsx-propose` | Cursor, GitHub Copilot (IDE), Devin Desktop, Trae, Oh My Pi |
| `.amazonq/prompts/opsx-<id>.md` | `@opsx-propose` | Amazon Q Developer |
| отсутствует — только навыки | `/openspec-propose` | CodeArts, ForgeCode, Hermes, Mistral Vibe, Zed Agent, общий `.agents` |
| отсутствует — Kimi Code | `/skill:openspec-propose` | Kimi Code |
| отсутствует — Codex CLI | `$openspec-propose` | Codex |

Devin — единственный инструмент, представленный в двух строках. Devin Desktop читает
`.devin/workflows/`, поэтому там работает `/opsx-propose`; [Devin Local
не читает](https://docs.devin.ai/desktop/devin-local) эти файлы, поэтому в нём
используйте навык `/openspec-propose`. Навыки, которые OpenSpec записывает в
`.devin/skills/`, работают в обоих инструментах; поэтому они ссылаются друг на
друга по имени навыка.

Все инструменты перечислены в разделе [Вызов команд](/ru-RU/supported-tools/#how-to-invoke) — эта таблица является источником истины. Две строки вообще не обозначают slash-команды: Amazon Q загружает файлы в библиотеку запросов и вызывает их через `@`, а в последних трёх строках используется имя *навыка*, не совпадающее с идентификатором команды (`/opsx:apply` соответствует навыку `openspec-apply-change`).

Если сомневаетесь, прочитайте строку «Начало работы», выведенную командой `openspec init`: в ней уже используется зарегистрированный для ваших инструментов формат. Также можно ввести slash и посмотреть варианты автодополнения, если инструмент их показывает.

## Откуда берутся команды: навыки и команды

При выполнении `openspec init` (или `openspec update`) OpenSpec записывает в проект небольшие файлы, чтобы ИИ-инструмент мог найти рабочий процесс. В зависимости от инструмента и настроек создаются **навыки**, **команды** или и то и другое.

- **Навыки** хранятся в каталогах вроде `.claude/skills/openspec-*/SKILL.md`. Это формирующийся универсальный стандарт: папка инструкций, которую ассистент обнаруживает автоматически.
- **Команды** находятся в каталогах вроде `.cursor/commands/opsx-<id>.md` или `.claude/commands/opsx/<id>.md`; структура зависит от инструмента и определяет синтаксис команды. Это более старые файлы slash-команд для отдельных инструментов. Для Codex файлы команд не генерируются; используйте `.agents/skills/openspec-*`.

Вам не нужно задумываться, какой вариант использует инструмент: достаточно ввести slash-команду. Но знание об этих файлах помогает при неполадках: если команды исчезли, обычно файлы отсутствуют или устарели; команда `openspec update` создаст их заново.

Точные пути для каждого инструмента см. в разделе [Поддерживаемые инструменты](/ru-RU/supported-tools/), а описание перехода от старого подхода только с командами к навыкам — в [Руководстве по миграции](/ru-RU/migration-guide/).

## Проверка установки

Короткие проверки в порядке возрастания сложности:

1. **Введите slash в чате с ИИ.** Начните вводить `/opsx` и посмотрите, появятся ли варианты автодополнения. Если да, настройка завершена. В инструментах, использующих только навыки (Codex, Kimi Code, CodeArts, ForgeCode, Hermes, Mistral Vibe, Zed Agent или общий каталог `.agents`), `/opsx` не дополняется даже при правильной установке — вместо этого попробуйте имя навыка из таблицы выше.
2. **Проверьте наличие файлов.** В Claude Code убедитесь, что в `.claude/skills/` есть папки `openspec-*`. Другие инструменты используют собственные каталоги (они перечислены в разделе [Поддерживаемые инструменты](/ru-RU/supported-tools/)).
3. **Повторите настройку.** В корне проекта запустите `openspec update`. Команда заново создаст файлы навыков и команд для настроенных инструментов.
4. **Перезапустите ассистента.** Многие инструменты ищут навыки и команды при запуске, поэтому может помочь новое окно.

## Какие команды доступны?

По умолчанию OpenSpec устанавливает набор slash-команд **core**:

- `/opsx:explore`: обдумать идею с ИИ до начала изменения (отличный первый шаг, если вы не уверены)
- `/opsx:propose`: создать изменение и за один шаг подготовить все артефакты планирования
- `/opsx:apply`: реализовать изменение, последовательно выполняя задачи
- `/opsx:update`: изменить артефакты планирования и сохранить их согласованность
- `/opsx:sync`: объединить обновления спецификаций изменения с основными спецификациями (обычно автоматически)
- `/opsx:archive`: завершить изменение и переместить его в архив

Хороший рабочий ритм по умолчанию: `explore`, если вы ещё определяетесь с задачей, затем `propose`, `apply` и `archive`. В руководстве [Сначала исследуйте](/ru-RU/explore/) объясняется, почему полезно начинать именно с этого шага.

Также доступен набор **expanded** для тех, кому нужен более точный контроль (`/opsx:new`, `/opsx:continue`, `/opsx:ff`, `/opsx:verify`, `/opsx:bulk-archive`, `/opsx:onboard`). Включите его командой `openspec config profile`, а затем примените с помощью `openspec update`.

Всё это для вас в новинку? Команда `/opsx:onboard` из расширенного набора проведёт вас через полный цикл изменения на собственной кодовой базе, поясняя каждый шаг. Это самый простой способ освоиться.

Подробное описание команд см. в разделе [Команды](/ru-RU/commands/), а рекомендации о том, когда какую команду использовать, — в разделе [Рабочие процессы](/ru-RU/workflows/).

## Чистый первый запуск

Ниже вся последовательность действий с указанием места выполнения каждого шага.

```text
ТЕРМИНАЛ   $ npm install -g @fission-ai/openspec@latest
ТЕРМИНАЛ   $ cd your-project
ТЕРМИНАЛ   $ openspec init
              (устанавливает slash-команды в ИИ-инструмент)

ЧАТ С ИИ     /opsx:explore
              (необязательно: сначала обдумайте идею с ИИ)

ЧАТ С ИИ     /opsx:propose add-dark-mode
              (ИИ составляет предложение, спецификации, проект и задачи)

ЧАТ С ИИ     /opsx:apply
              (ИИ реализует изменение, отмечая выполненные задачи)

ЧАТ С ИИ     /opsx:archive
              (изменение объединяется со спецификациями и архивируется)
```

Для настройки нужны два шага в терминале. Затем вся работа ведётся в чате. Таков рабочий ритм.
